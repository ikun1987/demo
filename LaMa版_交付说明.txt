二、怎么用（30 秒）
═══════════════════════════════════════════════════════════════════════════════
  1. 打开「玉用去水印」
  2. 把豆包保存的图片拖进窗口（支持一次拖一堆 / 整个文件夹）
  3. 确认右侧勾选 **「深度修补（LaMa）· 白色描边水印专用」**（默认已勾选）
  4. 点「开始去水印」
  5. 拖住预览中间的分割线左右拉动，逐像素对比

  输出：默认 图片\玉用去水印输出\xxx_已去水印.png
  ★ 原图永远只读，绝不覆盖。

  性能：单张约 8~20 秒（CPU 推理；首次使用多等几秒加载模型）。
        批量时模型只加载一次，后续每张更快。

  关掉这个勾选就退回传统算法 —— 适合「浅灰压暗」型老水印（那种能做到
  残差 44→1.2 灰阶、PSNR 79dB），且速度快（约 1 秒/张）。

三、为什么 LaMa 能解决传统算法解决不了的问题
═══════════════════════════════════════════════════════════════════════════════
  你这型水印是「白色填充 + 亮描边」的复合体，不是单一半透明覆盖，
  所以 alpha 反演的物理模型对它不成立；而 OpenCV 的结构感知修补
  （TELEA/NS）对"文字覆盖造成的结构性缺失"几乎没有重建能力 ——
  我实测过十几轮，最好也只是把字压淡、并在纹理背景上留下糊痕。

  LaMa（Large Mask Inpainting）是**专门为大块结构性缺失训练的修补网络**，
  它理解"这里本来应该长什么样"，因此能把水印覆盖的区域自然重建出来。

  实测对比（六张真实豆包图，"真实笔画残留 >5 灰阶"占比）：
      传统算法最好版本：  29% / 88% / 77% / 29% / 80% / 73%   ← 基本没去掉
      LaMa 路线：          0% /  8% / 33% /  0% / 38% /  7%   ← 字没了
  逐图看：1_点赞、4_正面、2_撸猫、6_气泡 完美；3_电脑、5_极客 也干净，
  只是背景本身复杂（灯杆、杯子）时修补痕迹稍多一点，肉眼仍看不出水印。

四、这条路线踩过的坑（都修好了，记录备查）
═══════════════════════════════════════════════════════════════════════════════
  传统算法部分：
    · 掩膜只按字模膨胀 → 真实字形比字模大一圈（宽高比 5.4 vs 5.0），
      左右与底边各漏几十像素，LaMa 照残留"画出"水印影子（越补越糟）；
      改成"实测字形外接矩形整块封住 + 余量"，残留从 88% 降到 8%。

  PyInstaller 打包部分（torch 冻结环境，四个坑全是实测打出来的）：
    · 排除 torch.distributed → 打包后 `No module named 'torch.distributed'`；
    · 排除 unittest → torch 顶层 import 它，直接崩；
    · setuptools 与 wheel 同时排除 → PyInstaller 自身报错；
    · 开 noarchive=True → 触发 torch 循环导入，改为关掉；
    · `inspect.getsource()` 在冻结环境取不到源码 → 直接崩进程（0xC0000409）；
      用 core/torch_fix.py 在 import torch 之前把那个只用于扫描注释的函数
      替换为空集（语义安全，不影响任何数值结果）；
    · PYTORCH_JIT=0 → TorchScript 权重加载失败（RecursiveScriptModule 无 _construct），去掉。

五、技术栈
═══════════════════════════════════════════════════════════════════════════════
  Python 3.12 + PySide6 6.11（界面）
  OpenCV / NumPy（传统算法：浅灰压暗水印）
  PyTorch 2.14 CPU + LaMa big-lama（深度修补：白色描边水印）
  PyInstaller 6.22（打包）+ Inno Setup 6（安装包）

  源码结构：
    app\main.py                  入口（含 torch 冻结环境加固）
    app\gui.py                   图形界面
    app\core\watermark.py        传统算法引擎
    app\core\doubao.py           豆包水印定位（字模多尺度匹配）
    app\core\lama_inpaint.py     LaMa 深度修补（掩膜 + 推理 + 融合）
    app\core\torch_fix.py        torch 冻结环境修补
    app\core\config.py           配置与开机自启
    app\assets\big-lama.pt       随包模型（196MB）

  一键重建：pwsh -File build.ps1
  交付终检：pwsh -File verify_delivery.ps1

六、已知边界（如实说明）
═══════════════════════════════════════════════════════════════════════════════
  1. 体积：含 PyTorch 与模型，安装包 321MB、装完约 811MB。这是走深度学习
     路线的必然代价；换来的是传统算法做不到的修复质量。
  2. 速度：CPU 推理约 8~20 秒/张（取决于分辨率与掩膜大小）。
     若有 NVIDIA 显卡，换 CUDA 版 torch 可提速数倍，但安装包会更大。
  3. 水印位置：目前依赖「右下角」先验（豆包默认位置）。若某张图水印在别处，
     用「手动框选」模式配合传统算法处理。
  4. 3_电脑 / 5_极客 这类"水印压在复杂物体边缘"的图，修补后细看背景纹理
     可能与周围略有差异（模型重建的固有特性），但水印本身已完全消失。
