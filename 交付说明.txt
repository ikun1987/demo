二、怎么用（30 秒上手）
═══════════════════════════════════════════════════════════════════════════════
  1. 打开「玉用去水印」
  2. 把豆包保存的图片直接拖进窗口（可一次拖一堆，也支持整个文件夹）
  3. 右侧「去水印强度」保持默认「强力」
  4. 点「开始去水印」
  5. 拖住预览中间的分割线左右拉动，逐像素对比处理前后
     （双击复位 · 滚轮缩放 · 按住拖动平移）

  输出位置：默认 图片\玉用去水印输出\xxx_已去水印.png
            勾「保存在原图目录」则输出到原图旁边。
  ★ 原图永远只读，绝不覆盖。

  快捷操作：Ctrl+O 导入 · Ctrl+R 开始 · Ctrl+S 另存 · Delete 移出列表
  关窗口会问一次「收进托盘 / 直接退出」（选过就不再问）。
  开机自启后自动缩到右下角托盘，双击托盘图标叫回主界面。

  命令行批处理（进阶）：
    玉用去水印.exe --out D:\去水印 D:\图库       处理整个目录
    玉用去水印.exe --s 5 --region br 图片.png    指定强度/位置
    玉用去水印.exe --check 图片.png              只检测不写文件
    玉用去水印.exe --help                        查看全部参数

四、为什么"不留涂抹痕迹"（技术链路）
═══════════════════════════════════════════════════════════════════════════════
  它不是"拿周围颜色涂一块"，而是**把被水印盖住的像素算回来**：

  ① 检测   局部背景残差找"比周围暗"的细长笔画 → 成行排布 + 低对比度双重先验
            确认是不是文字，避免把头发丝、衣褶当水印抹掉；
            背景估计用横/纵/对角三向中值取中位数，因此**亮度渐变底图也不会漏检**。
  ② 反混合 水印是半透明叠加。注意：教科书式的 (观测-a·水印色)/(1-a) 是**病态**的，
            系数只要差 1 个灰阶就被 1/(1-a) 放大，还会把底图纹理当水印剥掉。
            这里改用等价的稳健形式：
               rec = 观测 + clip(压暗量 / 该笔画满覆盖压降, 0, 1) × 满覆盖压降
            压降幅度直接来自观测，不依赖"水印色"估计，因此极淡水印也不会被放大、
            深水印最多抬到背景、绝不越界。
  ③ 修复   只对"完全被覆盖、反解不可靠"的像素做结构感知填充
            （Telea + Navier-Stokes 融合），再羽化过渡消灭硬边。
  ④ 渲染修复  对被文字压住的纹理按邻域重建，保住"原图意愿"。
  ⑤ 可见性判定  最后量化"实际改了多少灰阶"。干净照片误检出的那点噪声平均只改
            0.45 灰阶，而最淡的真水印也有 2.95 —— 相差 6 倍以上。低于门槛就
            **原样输出、不写文件**，并告诉你原因。

六、v1.1.0 新增：手动框选 + 强制清理（专治你那张"淡到抓不到"的水印）
═══════════════════════════════════════════════════════════════════════════════
  【先说 v1.0.x 的两个问题，都已修】

  ◆ 问题 1（界面 bug）：跑完看起来像卡死。
    现象：进度条停在 100% 不退、也没有任何弹窗，让人以为还在跑。
    原因：任务结束只把进度条设成满格、没复位，成功 0 张时也没有任何提示。
    修法：结束后自动复位进度条；成功 0 张时弹出可操作的提示框，并给一个
    「手动框选去试试」按钮，点一下直接切到手动模式。

  ◆ 问题 2（算法 bug，v1.0.1 已修）：它把你的**黑衣服**当水印剥了。
    证据：v1.0.0 在你这张图上改动的 768 个像素全部落在 x[959,1185] y[1170,1228]
    ——那是衣服，水印在最底边 y≈1265。它在剥衣服、没碰水印。
    根因：衣服褶皱同样"细长 + 比周围暗"，通过了形状判据，虚假压暗幅度高达 101 灰阶。
    修法：加**内容保护**判据——水印是压在**亮背景**上的浅灰字。实测被误判的 4 个
    分量背景亮度中位仅 25~52（衣服），水印处纸面背景 248~255，差 5 倍以上，
    一条门槛干净分开。修完在你两张原图上改动像素 0 个、位级一致。

  ◆ 问题 3（物理限制 + 新增解法）：这张图的字只有约 1 个灰阶，常规检测够不着。
    实测：全图纸张白像素 866,955 个，亮度 252~255 有 84 万、244~251 仅约 7 千且
    连续分布无字形聚集；用真实字体渲染「豆包AI生成」做归一化互相关，全图最高
    相关度仅 0.28（空白对照 −0.035），可靠检出需 0.5 以上；纸面自身噪声 σ≈1.4。
    → 常规算法到不了这个信噪比，所以工具会如实说"未检测到水印"。

    ★ 解法：新增 **强制清理（图章压平）** 模式，你手动框出位置，它来抹平：
      1. 右侧「水印位置」选「手动框选（极淡水印）」；
      2. 在图上按住左键拖一个框，把水印圈住（框内会显示尺寸）；
      3. 勾选「强制清理选中区域」，点「开始去水印」。

    它的安全边界（已实测）：只把**已经接近纸白**的像素抬回局部纸面基准；
    亮度低的像素权重为 0，**在数学上就抬不动**。
      · 你的图实测：改动 18,334 像素、平均仅 1.47 灰阶，
        深色内容（衣服/头发）最大改动 = **0.00 灰阶**；
      · 放大 14 倍可看出那层薄灰被抹平；原尺寸下看不出任何色块或边界。
    代价要说清楚：它会把框内纸面纹理略微抹匀（1~2 灰阶），这是"抹平"的必然代价。

  ★ 顺带一提：**常规模式仍然更强**。真水印（对比度 5~20 灰阶）走常规链路，
    实测残差 44→1.2 灰阶、PSNR 79.2 dB。手动框选只是给"淡到极限"的情况兜底。

七、量化验收（合成水印注入 → 去除 → 与干净原图逐像素比对）
═══════════════════════════════════════════════════════════════════════════════
  明显水印 α=0.35/灰128 : 残差峰值 44.2 → 1.2 灰阶  掩膜内最大误差 45 → 5（强度5：2）
  明显水印 α=0.35/灰200 :              19.2 → 1.2                19 → 4
  中等水印 α=0.20/灰128 :              25.2 → 1.2                26 → 5
  较淡水印 α=0.12/灰128 :              15.2 → 1.2                16 → 4
  PSNR（α=0.35/灰128）  : 47.94 → 79.2 dB
  干净照片误伤          : 最大改动 0.00 灰阶、改动像素 0 个、检出 0 个、PSNR 168 dB（位级一致）
  内容保护              : 深色内容区域 0 改动（v1.0.0 会误剥，现已修）
  强制清理              : 深色内容 0 改动；纸面抬平 1~3 灰阶
  鲁棒性                : 检出率 57/60；平坦/人像底图掩膜内平均误差 0.15~0.22
  边界                  : 16×16 / 6000×400 / 灰度 / RGBA / 中文含空格文件名 全部正常
  性能                  : 1280×1280 单张约 0.9~1.4 秒

  已知局限（如实说明，不粉饰）：
  1. 合成强噪声/纹理底图 + 最淡档（α=0.10）时，该用例"掩膜内平均误差 5.14"里
     绝大部分是**噪声本身**而非残留水印（合成纹理 σ=6，水印落差仅 1.3 灰阶）。
  2. 极淡档（水印落差 < 2 灰阶）位于左下角时有 3/60 未检出，属物理不可见档。
  3. 若真实水印在**同一笔画内不透明度差异很大**（如渐变遮罩），本算法按连通域
     统一压降校正，精度不如"水印不透明度均匀"的情况。

六、关于你给的那张实验图（重要，请看一眼）
═══════════════════════════════════════════════════════════════════════════════
  你给的 5523db9b...png 我做了像素级解剖：**它里面没有可检测的水印结构**。
  证据：对全图 869,318 个"纸张白"像素做局部背景残差分析，最强结构只有 7 个灰阶，
  且是 545 个零散小点（JPEG 噪声），既不成字形、也不在右下角。

  所以这张图无法用来"调参验证"。我改用**可量化的合成回环测试**：
  用系统真实中文字体渲染「豆包AI生成」字模，按不同透明度/字号/位置注入到干净
  原图上，跑算法后再与干净原图逐像素比 PSNR 与最大误差。第五节数字即由此而来。

  因此：把这张图拖进软件，它会告诉你「未发现可见水印，原图已干净，未写出文件」。
  这是**正确行为**——它本来就没有需要去掉的东西，而不是软件坏了。

  ★ 如果你手上有水印"看得见"的豆包图，发我一张，我可以用它把字模匹配再精调一档。

七、技术栈与可复现构建
═══════════════════════════════════════════════════════════════════════════════
  Python 3.12 + PySide6 6.11（界面）+ OpenCV 5.0 / NumPy（算法）
  PyInstaller 6.22（打包）+ Inno Setup 6（安装包）

  一键重建：  pwsh -File build.ps1
              会先跑算法自测，再生成图标、打包 exe、编译安装包。
  交付终检：  pwsh -File verify_delivery.ps1
              算法套件 + exe 启动 + 静默安装 + 自启注册表 + 卸载清理 全链路。

  源码结构：
    app\main.py              入口
    app\gui.py               图形界面（含托盘、开机自启、命令行模式）
    app\core\watermark.py    去水印算法引擎
    app\core\config.py       配置与开机自启（写 HKCU\...\Run）
    app\selftest.py          算法回环自测（22 用例）
    app\make_icon.py         图标生成
    app\build.spec           PyInstaller 配置（含瘦身步骤）
    installer.iss            Inno Setup 安装脚本
