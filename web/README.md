# 玉用去水印 · 网页版（移动端优先）

豆包导出图上那层「豆包AI生成」水印（白色填充 + 亮描边）的清除工具。
**纯浏览器本地处理，图片不上传任何服务器**，断网也能用（首次需下载一次 AI 模型）。

- 桌面版（Python + PyInstaller）：见仓库根目录 `app/`
- 网页版（Vue3 + Vite + ONNX Runtime Web）：就是本目录

---

## 手机上怎么用

1. 浏览器打开部署好的网址（建议 Chrome / Safari 或微信内置浏览器）
2. 点「选择图片」，选一张豆包导出的图
3. 点「开始去水印」，等几秒（首次会先下载约 60MB 模型，**建议 Wi-Fi**）
4. **长按结果图 → 选「存储图像 / 保存图片」**即可存到相册
   （若长按没反应，点「保存到相册」按钮；iPhone 用 Safari 最稳）
5. 拖动中间滑块可左右对比原图与结果

水电建议：把网页「添加到主屏幕」，用起来跟 App 一样。

## 技术路线

### 为什么不是把桌面版搬上来

桌面版用 PyTorch 跑 LaMa，`big-lama.pt` 有 196MB，浏览器跑不了。
所以网页版换成 **ONNX Runtime Web + 量化后的 LaMa**：

| 项 | 桌面版 | 网页版 |
|---|---|---|
| 推理引擎 | PyTorch 2.14 CPU | onnxruntime-web 1.20（WASM，GPU 可用时走 WebGPU） |
| 模型 | big-lama.pt（196MB） | lama_512_int8.onnx（59MB，int8 量化） |
| 部署 | 安装包 321MB | 静态站点 29MB（模型走 CDN 按需下载） |
| 速度 | 约 9 秒/张 | 约 15 秒/张（中端手机；桌面浏览器更快） |

模型来自 [g-ronimo/lama](https://huggingface.co/g-ronimo/lama)：
官方把 LaMa 导出成固定 512×512 的 ONNX，并把 FFT 换成矩阵乘，
这样每个算子都能跑在浏览器上（含 WebGPU）。`lama_512_int8` 是官方推荐的移动端选择。

### ⚠️ 模型下载源（重要）

**实测中国大陆直连 `huggingface.co` 完全不通**（curl 21 秒超时、0 字节），
所以代码里把 **`hf-mirror.com` 放在第一位**、HF 作为兜底，并给下载加了超时
（8 秒内没拿到首字节就切下一个源，不会让用户干等半分钟）。

如果镜像哪天不可用，最稳的做法是把模型传到**本仓库的 Release 附件**，
然后二选一：

```js
// 方式一：在 index.html 里前置指定（推荐）
window.__LAMA_MODEL_URL__ = 'https://github.com/<user>/<repo>/releases/download/v1/lama_512_int8.onnx';
```

```js
// 方式二：改 web/src/lib/lama.js 里 DEFAULT_URLS 的顺序
```

也可以把模型放到自己的对象存储 / CDN，只要支持 CORS 与 Range 请求即可。

### 三个必须踩过才知道的坑

1. **输入图的掩膜区必须置零。**
   模型卡写明：通道 0-2 是「掩膜区被涂掉的图」。不置零的话模型把白色水印当内容，
   输出一片白。实测过。

2. **要「裁剪局部」再修补，不能整图缩到 512。**
   一张 1706 宽的图缩到 512 后，水印只占约 48px，模型没有细节可用，
   重建结果是糊的，杯子底边、镜框边缘都会被抹掉。
   正确做法：把掩膜区连同周边上下文抠出来、放大到 512 再修补，最后贴回。
   残留从 60%+ 降到 6%。

3. **掩膜要往右、往下多留余量。**
   实测豆包水印比渲染出来的字模「右宽下厚」，均摊余量会在右边和下边各漏一段笔画；
   漏掉的部分会被修补网络当上下文，原地「重画」出一层浅色残字。

### 水印定位

用真实中文字体把「豆包AI生成」渲染成字模，在右下角做多尺度模板匹配：

```
score = 覆盖率 × 0.75 + min(笔画处平均偏离 / 30, 1) × 0.25
覆盖率 = Σ偏离(字模笔画处) / Σ偏离(字模窗口全部)
```

必须以覆盖率为主：小字模只覆盖窗口一小部分能量，会被天然惩罚；
错位的字模压不到笔画，分也低。曾试过「峰值能量×覆盖率修正」和
「能量最大矩形」两种替代打分，都会被猫毛、条纹这类高对比纹理骗到，**都不行**。

性能上做了两件事：偏离图全图只算一次（桌面版每尺度重算是笔误级浪费）；
背景估计从 O(n·k) 的可分离中值换成 O(n) 的「盒式均值 + 局部最小值」，
单张定位从 13~28 秒降到 **0.65 秒**。

## 本地开发

```bash
cd web
npm install
npm run dev            # 开发服务器（含模型代理，避免 CORS）
npm run build          # 产出 dist/
```

部署到 GitHub Pages 时 `base` 必须是 `/<仓库名>/`：

```bash
BASE=/demo/ npm run build
```

仓库根目录的 `deploy-web.ps1` 会自动带上正确的 base 并推送。

## 测试

```bash
# 检测/掩膜算法单测（Node + node-canvas，比对 Python 版结果）
node ../webtools/test-detect.mjs

# 真实浏览器端到端测试（Playwright，跑完把结果图落盘）
node ../webtools/e2e.mjs ../testimages ./e2e-out
```

`webtools/node-infer.mjs` 用 onnxruntime-node 跑**与浏览器完全相同的算法**，
用于把「算法问题」和「浏览器环境问题」区分开 —— 排障时非常有用。

## 已知边界

- 模型固定 512×512，所以修补质量取决于「掩膜区放大到 512 后的清晰度」。
  超大图（>2400px）会先缩到 2400 再做，避免手机内存爆掉。
- 水印压在复杂硬边（杯沿、镜框）上时，边界会被轻微柔化 —— 这是 LaMa 重建的固有特性，
  水印本身已经完全消失。
- 目前只覆盖「右下角」先验。水印在别处时用「手动涂抹」自己圈出水印区域。
- 首次使用要下载 59MB 模型，之后由浏览器缓存，二次使用无需联网。
